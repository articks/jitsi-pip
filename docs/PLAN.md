# План разработки

## Цель

Создать standalone-плагин для Jitsi Meet 2.0.11146, подключаемый одним JavaScript-файлом без изменения и пересборки Jitsi.

## Этапы

1. ✅ Подготовить изолированный TypeScript-проект и документацию.
2. ✅ Реализовать адаптер к `window.APP`, Redux store, участникам и видеотрекам Jitsi.
3. ✅ Зарегистрировать пользовательскую кнопку toolbar и публичный API.
4. ✅ Реализовать Document Picture-in-Picture для четырёх активных собеседников.
5. ✅ Реализовать Video Picture-in-Picture fallback с одним собеседником.
6. ✅ Добавить Media Session Auto PiP и управление микрофоном, камерой и завершением звонка.
7. ✅ Добавить unit-, контрактные и локальные Docker-тесты.
8. ✅ Собрать и проверить единый `dist/jitsi-meet-pip.min.js`.
9. ✅ Развернуть изолированный Jitsi `stable-11146-1` в локальном Docker и проверить кнопку, BOSH и конференцию с несколькими участниками.
10. ✅ Доработать нативный Auto PiP Chrome: причины Media Session, capture state и пользовательская диагностика.
11. ✅ Повторно активировать Auto PiP после старта локального capture, добавить readiness API и cache-busting сборки `1.1.1`.
12. ✅ Добавить silent-conference fallback: показывать подключённых удалённых участников до появления dominant/active speakers; сборка `1.1.2`.
13. ✅ Исправить ложную диагностику разрешения на HTTP, добавить protocol eligibility и локальный HTTPS-профиль; сборка `1.1.3`.
14. ✅ Не открывать Auto PiP повторно после ручного закрытия в рамках текущей сессии; сборка `1.1.4`.

## Критерии готовности

- Плагин не требует runtime-зависимостей и пересборки Jitsi.
- Существующие пользовательские кнопки Jitsi сохраняются.
- В Document PiP отображается от одного до четырёх удалённых активных собеседников.
- Переключение говорящих не создаёт дублирующий звук и утечки прикреплённых треков.
- Ручное и автоматическое открытие различаются поведением при возврате в Jitsi.
- Все проверки проходят локально, а содержимое проекта находится только в `jitsi-meet-pip`.
